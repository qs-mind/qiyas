# W5: built-in drafting and design knowledge — 27 October 2026

The partial implementation in `3ebd86b` is now connected to the command registry and
Mizan's existing generic tools. This is a code handoff, not a verified build: no
build, test, lint, formatter, package-manager or application check was run, by instruction.

## What changed and why

- Registered `drafting_standards` and `space_planning` as public core modules.
  `query::plain_text`, the number conversion helpers and `Session::sheet_language`
  were already reachable; no visibility changes were necessary.
- Added read-only inquiry commands `drafting_knowledge` and `space_check`, returning
  `Outcome::Measurement`. They have no undo part. Knowledge covers sheet sets,
  view requirements, symbols, materials, planning thresholds, codes, limits and
  general notes. Space checks cover circulation, room sizes and proportions,
  bathroom provision, master en-suite, wardrobes, stair clearances/enclosure and doors.
- Made the planning room-reference lifetimes explicit. Reject non-finite positions,
  invalid leaf counts and invalid stair dimensions. A bathroom with unknown access
  now leaves the en-suite rule unchecked, including when another bathroom has known
  public access; unknown evidence must not become a failed check.
- Added `symbol`, a draw command with document/table undo, using existing `draw`,
  hatch, text, dimension-leader and reusable block APIs. There is no second geometry
  or annotation engine. Current drawing state is restored on success or failure;
  the ordinary command transaction owns rollback and undo.
- `symbol.door`: single/double leaf lines and quarter-circle swings, either side,
  rotated along the opening. Omitted leaf count uses the existing labelled
  double-leaf threshold. Identical local recipes reuse blocks. These standalone
  symbols do not cut walls; hosted openings still use wall commands.
- `symbol.stair`: a straight flight with UP, a cut mark and hidden treads above the
  cut on its lower floor; DN, a full descending flight, adjacent void and handrails
  on its upper floor. Width is flight width; the upper void takes another width
  on its left. Rotation and sheet-language labels are supported. For L/U stairs,
  compose flights and draw the landings explicitly. This does not design a stair,
  calculate headroom, enclose it in walls or infer its floor from nearby geometry.
- `symbol.levels`: supplied FFL/roof/parapet names and signed, two-decimal metre
  elevations relative to an explicit origin. `symbol.ground_line`: a heavy line
  and soil ticks. `symbol.foundation_level`: a dashed datum labelled indicative,
  with the supplied elevation; no foundation size or depth is invented.
- `symbol.material_hatch`: material-table patterns, heavy section/detail cut
  outlines (including hole outlines), and leader labels. Elevation materials
  without a pattern get their leader only. Labels may specify the user's material,
  thickness and finish. Pattern spacing and annotation sizes follow paper scale.
- All symbol examples use scalable drawing-coordinate names (`a`, `b`, `origin`,
  `side_point`, `point`, `at`, `points`, `width`). `_m` inputs remain metres. This
  lets the existing `own_output` guard replay them in mm, cm, m and inches without
  changing that test. Layout coordinates remain paper millimetres.
- Mizan discovers all three commands through the registry. Two local description
  edits in `surface.rs` advertise them through `qiyas_read run` and
  `qiyas_execute run`/`batch`, like other registry commands. No extra operation or
  parallel schema was introduced; the other agent's export work was preserved.
- Added `w5_drafting.rs` to the existing `tests/all.rs` binary. Fixtures cover the
  founder's corridor villa, a good villa across the available markets, incomplete
  en-suite evidence, read-only commands, leaf/swing geometry and block reuse,
  stair floor differences, elevation/ground/foundation symbols, section/detail
  hatch scale and leaders, undo/redo, rollback and register provenance.
- The existing registry-index ceiling was raised from **4,500 to 5,000 bytes** to
  accommodate the new command names and six symbol kinds. The exact generated
  size is unmeasured in this run; the deferred registry test must confirm it.
  Existing test edits are only that ceiling and the requested `tests/all.rs` entry.

## Sources and their actual evidence status

The JSON files from `3ebd86b` are unchanged. Sources and limits below are inherited
from `crates/qiyas-core/data/code-register.json`; this run did not fetch or newly
verify them. A presence check is not proof that a source is current or authoritative.

- Egypt's numeric code limits cite the [Andersen English translation](https://eg.andersen.com/translation-of-law-no-119-of-2008/).
  The register says this translation was read, and requires checking its article
  numbering and content against the official Arabic text. The ministry URL is
  [mhuc.gov.eg](https://www.mhuc.gov.eg), marked not read in the register.
- Egyptian structural-code names have weaker evidence: [HBRC](https://www.hbrc.edu.eg),
  an [engineers' forum](https://www.eng-tips.com/viewthread.cfm?qid=405210),
  a [UNEP legislation entry](https://leap.unep.org/en/countries/eg/national-legislation/resolution-no-139-2001-concerning-egyptian-code-soil-mechanic-and)
  and an [HBRC codes-page mirror](https://demosites.mans.edu.eg/hbrc/en/activities/codes).
  The register marks these as named in sources, with unverified editions and some
  unverified number/title pairings. No structural design values are derived from them.
- Saudi code names come from the [SASO inspection-body list](https://www.saso.gov.sa/en/sectors/product-safety/Documents/SBC-INSP-EN.pdf),
  linked to [the Saudi Building Code committee](https://www.sbc.gov.sa). The register
  says the list was read, not the code text. (Superseded the same night: see "Amendments,
  KSA and UAE verified" below.)
- Dubai's code existence comes from the [Dubai legislation decree](https://dlp.dubai.gov.ae/Legislation%20Reference/2021/Decree%20No.%20%2845%29%20of%202021%20Concerning%20the%20Dubai%20Building%20Code.html)
  and [Dubai Municipality](https://www.dm.gov.ae/). The register says the decree was
  read, not the villa provisions of the building code.
- Abu Dhabi's adoption and the UAE fire-code link come from the [ICC adoption page](https://www.iccsafe.org/international-code-adoptions/united-arab-emirates/).
  The register also links the [department building-code page](https://dmat.abudhabi.ae/en/About/Pages/buildingcode.aspx)
  and [Civil Defence PDF](https://www.dcd.gov.ae/portal/eng/UAEFIRECODE_ENG.pdf), marked
  not read. (Superseded the same night: Dubai Building Code 2021 values now read; see below.)

`check_register()` enforces a code name, clause and HTTPS source for each value
labelled `code`, or a `practice_default` label and rationale without spurious code
citations. Drafting conventions and planning heuristics are practice, not code.
No code clause or numerical code requirement was added in this work.

## Egypt limits verified (27 October 2026, evening)

The 22 Egypt limits were checked against the Arabic text of the executive regulations
(decree 144/2009, Articles 93, 94, 96, 97, 100 and 103). Every figure matched, and they are code values again. Each
one quotes its Arabic article (`quote_ar`) and carries this caveat in its note:
- the text was read on a legal-reference site (https://lawyeregypt.net/?p=3758), not the
  gazette;
- that copy is the 2009 text, and decree 774/2014 amended "certain provisions" that were not
  read.
For stair width, only the 1.10 m figure (up to four units per floor) is cited.

## Amendments, KSA and UAE verified (27 October 2026, night)

**Egypt amendments.** Nine later decrees amending the executive regulations were read:
200/2010, 109/2013, 272/2013, 774/2014, 296/2021, 410/2021, 943/2024, 120/2025 and 1505/2025.
None changes any of the 22 values. Decree 774/2014 only replaces Article 134 and some forms.
Decree 109/2013 re-enacted Articles 94 and 100 with the same numbers. Those limits now cite
"Article 94/100 (text substituted by decree 109/2013)" and point to the Gazette scan
(https://manshurat.org/sites/default/files/docs/pdf/006830.pdf). Decree 67/2014 could not be
read, and every Egypt note says so.

**KSA.** Thirteen limits are now code values, from MOMAH's Residential Buildings Construction
Requirements (decree 1/4500943139, 2024; the November 2025 re-issue has the same values). The
Arabic PDF is on momah.gov.sa. Each limit quotes it in `quote_ar`. The thirteen are:
- room sizes: room, kitchen, bathroom and WC areas and widths;
- corridor;
- villa entrance;
- daylight glazing;
- main stair width (villa value; apartment buildings need 1.2 m, stated in the note);
- guard height of 0.9 m (balconies everywhere, railings in apartment buildings).
The ministry text refers several values to SBC 201/1101, whose numeric text is not public. Those
stay practice defaults: ceiling heights, risers, goings, steps per flight, headroom, inner door
widths, service window ratio and window sill.

**UAE.** Fifteen limits are now code values, from the Dubai Building Code 2021, Part K (villas),
read in Dubai Municipality's PDF. Administrative Resolution 225/2024 was read and changes none of
them. Each limit quotes the code in `quote_en`. Its note gives the Dubai apartment (Part B) value
and the Abu Dhabi private-villa value (DMT Private Housing Manual 2022) wherever they differ.
The register's single UAE market means Dubai villa values are the ones checked. Inner room doors,
service window ratio and steps per flight stay practice defaults.

Not read: Abu Dhabi apartment provisions and the federal Fire and Life Safety Code, because no
official copy was reachable.

The test `gulf_code_findings_cite_their_document_and_the_rest_stay_practice_defaults` covers both
markets.
