The request is built correctly: `chatgpt_plan/responses.rs` sends the same `instructions`, `tools` and
`prompt_cache_key` and an `input` that only grows at its end, and the new test
`a_long_turn_only_appends_between_trims_and_a_trim_rewrites_the_prefix_once` proves it over a 40-step
turn, through a trim, and for 10 more steps. So the misses in the second row are not caused by how the
body is built. A request 10-30 seconds after the previous one that repeats the same 3 k tokens of
tools and instructions and still reads 0 cached tokens points at the provider (routing or eviction),
which Qiyas cannot see or steer beyond the cache key it already sends.

What W1 changes for cost, therefore, is volume and rebuilds, not the key: results are 3-5 times smaller
(rows, pointers, contracts with examples, no repeated schema lookups), the efficiency note no longer
adds a message to every request, and fewer calls means fewer trims. **Needs the founder or the plan
reviewer:** whether the ChatGPT Responses service accepts `prompt_cache_retention` (extended retention)
or a session header; I did not send either, because an unsupported field would make a turn fail and
no live call was possible.

## What changed, by item

1. **Questions.** New operation `qiyas_execute ask` (no new tool): `questions` 1-6, each with 2-4 options,
   at most one `recommended`, `allow_other` always true. `AgentEvent::Question {questions}` ends the
   turn (no `Done`, status "waiting"); the answer is the next user message. The existing panel shows a
   numbered list with lettered options (`kind: "question"`), saved and restored like any event.
   Tests: `tests/w1.rs` (`several_questions_go_out_in_one_event...`, `the_answer_to_a_question...`,
   `a_bad_question_is_an_error...`, `ask_is_an_operation_with_a_contract...`), `messages.test.ts`.
2. **Assume, do not ask.** Both prompts; `[state]` gets `Country/practice` from the new Settings field
   `country` (Settings dialog has an input), else from the method name (Egypt, KSA, UAE), else "ask once".
3. **Cost advice.** Reworded as efficiency advice; given once per turn each as the `[efficiency note]`
   message and the `tool_cost` advice, never "subscription cost", always "not a reason to stop".
   "Continue" and similar messages add a `[continue]` note naming the open phases and keep the job.
   Tests: `the_cost_note_is_given_once_and_never_says_to_stop`, `continue_resumes_the_open_phases...`,
   `judgement::tests`.
4. **Finish gate.** `PlanWatch::finish_gate`: refused while phases are pending or active, naming them,
   unless the user said stop, the reply ends with a question, a metered run said `[finish now]`, or it was
   refused twice for the same plan. Applies to the `finish` operation, to a plain end of turn, and to the
   MCP `finish`. Tests: four in `tests/w1.rs`, `plan_watch::tests`.
5. **Draw on assumptions.** Prompt: Qiyas draws, loads/design calculations/approval are the engineer's
   and the company's; missing verified data is never a reason to refuse; assumptions go on the sheet as
   general notes (status "For review") and in the answer; never claim approval or code compliance.
6. **Fewer wasted calls.** See the replay above: `rows` projection of long lists, `artifact` `pointer`,
   `kinds_contract`, oversized-record shortening with the tables hint, `commands` up to 40 names (was 16),
   lenient `fields` on records and other reads. Tests: three in `result.rs`, one in `artifact.rs`.
7. **Cache.** Evidence and test above; no change to the key.
8. **Save.** `Agent::keep_work`: a titled drawing is saved through the host after a phase that changed it
   (and again at the end if still changed); an untitled one is asked once at the end through the window's
   Save As, and the answer says so. Tests: three in `tests/w1.rs`.
9. **Reply language.** An answer clearly in the other language than the latest message (60+ letters, one
   language well ahead) is sent back once. Tests: two in `tests/w1.rs`, `judgement::tests`.
10. **Exports.** `quantity_gate` on `export_takeoff` and `deliverable.export` (boq, dimensions, variation)
    for Mizan and MCP: refused with `quantity_check_failed` while `takeoff_check` has measurement errors
    or unmatched schedule rows; a file named with DRAFT goes through, marked in its name and in the
    answer (`draft_export` advice, "tell the user"). Test: `quantities_are_not_exported_after_a_failed_check...`.
11. **Tool surface errors.** `commands names` maxItems 16 to 40 (note 3); `records fields` that no record
    has now warn instead of failing the call (the day's 13 refused reads: `hidden`, `points`, `quantity`,
    `cells`, `table`, `/insertion_point`); `fields` on `run`, `query` and others accept a path without its
    first slash and name `missing_fields` instead of failing. Not changed: `spatial_query` on a wall
    system ("no exact curves"), `label_spaces` in a batch (W3/W5), and a collection name the model invents
    (the error already lists the valid ones).

Prompts: English 823 words, Arabic 871 (limit 900, tests count both).
