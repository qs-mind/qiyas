# W3: what Qiyas and Mizan hand to a client (27 October 2026)

The founder tested Qiyas for a day and the sheets, schedules and BOQ were poor. This report
covers notes 21 to 39 and 54 to 62 of his list that are about output, the root cause of each in the
engine, the fix, its test, the before and after evidence, and what is not done. Notes about design
quality (35 m² lobby, stairs, elevations, sections, details, codes) are W5, not here.

Tests, all in every unit (mm, cm, m, inches) where a length is involved:
`crates/qiyas-core/tests/w3_output.rs`, `crates/qiyas-boq/tests/w3_workbook.rs`,
`crates/qiyas-plot/tests/plot.rs` (export folder), `crates/qiyas-ai/tests/w3.rs` (the offline replay),
unit tests in `numbers.rs`, `quantity_notes.rs`, `sheet_setup.rs`, `digest/note_scope.rs`.

## Decisions the founder should know

* A line the engine cannot buy (gross floor area) is left out of the BOQ by its own words in English
  and Arabic and by an explicit flag. The words are a safety net; the flag is the rule.
* Doors and windows are the only objects whose BOQ code the engine extends. A client BOQ is matched by
  code, so another object type keeps the mapping's code. A client BOQ with one "doors" row now compares
  against several generated rows by size.
* An Arabic BOQ drops an English-only method column instead of printing English in it (the report says
  so, the dimension sheets keep it). Mizan can write Arabic clauses to show it.
* A short-wall deduction no longer stops the method; it is limited to zero and reported as a warning.
  The founder may prefer a hard stop; the choice is one line in `measurement/evaluate.rs`.

## Skills used, and skipped

* rust-skills: error handling in the new commands (no panics, typed errors), `Box` for the large command
  variant (clippy), no new `unsafe`; incremental-implementation: one slice at a time, a test for each.
* dimensional-analysis: every number a client reads is a metre, a square metre or a piece, converted in one
  place (`numbers.rs`); the sheet maths is paper millimetres against model units through `to_metres()`, tested
  in mm, cm, m and inches.
* property-based-testing: a dependency-free table of cases for number and unit formatting and the id finder
  (the repo has no proptest and the brief asks for no new dependency); the totals and the itemisation rules
  are tested as properties of the data (no total across codes or units; one line per size).
* spec-to-code-compliance: each brief item was read against the code that prints it, which found the real
  causes (the advice that asked for `takeoff:<id>`, a hard failure on a viewport, a sheet number read as
  a handle).
* debugging-and-error-recovery: the replay failures were localised and fixed at their cause, not worked round.
* code-review-and-quality: a read of the diff for scope, and clippy and fmt clean.
* Skipped on purpose: frontend-design and baseline-ui (no window code changed), llm-evaluation (no live model
  run was allowed), performance skills (no hot path changed; the placement now asks for the viewports' frames,
  which is one model batch per call and only on a layout).

## Not done

* The design of the drawings themselves (lobby, kitchen, stair, entrance, elevations, sections, details,
  code register) is W5.
* Notes 21, 24 and 59 (text over lines, text heights, dimensions over a stair or a label): Goal G gave the tools
  and `make_sheet` and the placement above remove two blockers, but the quality of what Mizan draws on the
  plan is the design work of W5. `make_sheet` reports the least model text height that reads at its scale
  (`min_text_height`); nothing sets the annotation scale of Model by itself.
* The take-off kit batch (`takeoff_kit`) does not contain `object_tags` or `make_sheet`: the kit's 6,144-byte
  guard is full, so the workflow and the prompts name them. A BOQ comparison against a client BOQ that has
  one row for all doors now meets several generated rows.
* No live Mizan run and no paid run: the replay is a script, so it proves the engine and the orchestration,
  not what a model chooses.
* Not looked at in the real window (headless only): the Excel band and the PDF spacing of section rows are
  checked by their text and by the structure of the workbook, and the PDF page images above; the workbook was
  not opened in a spreadsheet program.
