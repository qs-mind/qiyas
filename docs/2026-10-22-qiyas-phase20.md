# Phase 20: revisions and variations

The shared registry now exposes `compare_revisions {other_path,tolerance?}`,
`carry_knowledge {from_path,tolerance?}` and `variation_report {layer?}`. The drawing
on screen is B; the supplied other/from path is A. Command-line words are
COMPAREREVISIONS, CARRYKNOWLEDGE and VARIATIONREPORT. The generic Mizan tools use
the same commands. The take-off kit includes complete minimal revision examples;
the workflow index and take-off instructions describe opening B, carrying A,
re-taking-off and producing the variation and clouds.

The engine compares top-level source entities on every named sheet. Entity data
includes block definition contents and attributes, with codec ownership, caches
and Qiyas annotations removed. Exact geometry is reserved before changed handles
are trusted, detecting handle-renumbered exports. Remaining geometry matches use
layer, block, kind and unique mutual proximity. Ambiguous matches remain additions
and removals. Tolerances are in drawing units; the default is the existing
measurement tolerance. It applies to coordinates and linear dimensions; colours,
flags, angles, scales and properties still compare exactly. Drawings in different units must be converted first.
Comparison returns per-sheet changes and their bounds, including removed geometry.

Carry stores A's source snapshots and measured BOQ in B's `revisions/baseline`
knowledge record. Types, recognition, methods, mappings, tables and cited checks
carry over, with handle references remapped. Recognition decisions on B are cleared
and extraction is reapplied on all sheets. Authored instances retain their supplied
properties when B has no replacement. A separate revision identity survives handle
changes; local object ids remain their CAD driver handles. Object records expose
`identity`, and BOQ `{id}` templates use it to keep item codes stable.

Variation rows give bilingual descriptions, unit, A quantity, B quantity and delta.
Dimension contributions are paired through source identities, retaining A and B
handles and signed contributions for additions, removals and changed elements.
Different units remain separate rows. No rates or trade/standard rules are added.
Measurement warnings are retained. Re-running the report replaces its own clouds,
using the existing Comment implementation. The layer is supplied or retained as
`revisions/cloud_layer` data, defaulting to VARIATION. Clouds and report metadata
are one drawing undo step; carry is also one step. A wholly removed sheet is
reported with a warning because it has no sheet in B on which to draw its clouds.

All take-off workbook export hosts include a Variation sheet when the drawing has
a variation report. The sheet has readable English/Arabic quantities and evidence,
plus chunked JSON record cells for lossless import through
`qiyas_boq::variation::import_variation`. Chunking avoids Excel's text-cell limit.
The stored report and Comment clouds survive standalone DWG/DXF save and reopen.

`qiyas-cli variation A B --export x.xlsx [--drawing-output clouded-B.dxf]` runs the
carry/report flow offline and writes the workbook. The optional drawing output
retains clouds and embedded knowledge without needing a script. It does not access
provider configuration or credentials.

## Benchmark separation

The existing `bench run --set quick --mode prepared|autonomy` now also scores the
revision-B cases in that frozen cohort. It uses the production commands and writes
A, clouded B, Variation workbook and prediction JSON before the scorer reads truth.
Each case checks workbook and drawing persistence. Prepared uses A's interpretation
recipe plus shared fallback rules with explicit lower priority; autonomy uses only
shared recognition data. These are engine diagnostics,
not a live MIZAN ALONE evaluation. No metered model calls were made.

The scorer matches changed items by source evidence and unit, records recall and
precision, and checks signed deltas using the existing count/geometric/rule/judgement
tolerance classes. Every case reports elapsed time including interpretation, carry,
measurement, clouds, exports and persistence checks. Prediction failures remain in
the denominator. The existing take-off and discrepancy scores remain unchanged.
`bench revisions --set quick --mode prepared|autonomy` runs only the revision cohort,
without replacing the general take-off baseline.

Development artifacts and check logs are under `.local/phase20/` and the benchmark
run directories. No new crates, staging, commits or pushes are part of this work.
