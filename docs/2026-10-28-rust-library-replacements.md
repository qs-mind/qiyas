**4. Behavior differences, decisions and API evidence**

| Area | Possible difference and reason |
|---|---|
| Line opportunities | CJK, hyphens, punctuation and Unicode separators can wrap at different positions under UAX #14. The viewport additionally recognizes mandatory Unicode line separators when wrapping is enabled. This can change row heights, text boxes, picking and PDF pagination. No new shaping engine or measurement units were introduced. |
| Whitespace | ASCII spaces retain viewport advances and report collapsing. NBSP/narrow NBSP in reports are now preserved, and runs containing NBSP, narrow NBSP, word joiner or BOM are not emergency-split. Such a run can overflow a narrow report cell; this is the deliberate no-break policy. Report paragraph boundaries remain newline-based and other breakable whitespace is still collapsed. |
| Graphemes | Combining sequences and emoji are no longer split by report emergency breaks or font itemization. A font covering the entire grapheme wins; otherwise its base selects the face. A mark can therefore remain a missing glyph in that face instead of moving into a separate fallback run. This protects shaping clusters and can change advances where the old fallback split a cluster. |
| Unicode properties | Script extensions cover Arabic outside the old blocks, and general categories recognize all decimal digits and letter categories. Bidi triggering now uses actual RTL/Arabic-number/control classes. Characters merely inside an old broad range, but without these properties, can take a different path. Visual Arabic reversal keeps extended graphemes together and retains their original starting byte offsets. |
| Search | Unicode simple folding matches cases such as Greek final sigma; whole-word boundaries include combining marks, join controls and Unicode connector characters. It remains literal, non-overlapping and does not implement multi-character folding such as sharp-s to `ss`. Regex compilation can refuse an exceptionally large literal under its resource limit rather than using the old unrestricted scan. |
| System fonts | fontdb uses platform discovery, without the old depth limit. Duplicate filenames can resolve in its discovery order. Within a collection, normal style and weight nearest 400 win, then the lowest face index. Family-name fallback is tried only after filename matching. These choices can change real-machine typography, while bundled-only fonts remain independent of the machine. The chosen face is used consistently by PDF metrics, outlines and subsets. |
| Raster pixels | Nearest sampling remains. Tiny-skia owns edge coverage, rounding and premultiplied source-over math, so edge pixels and color channels can differ, commonly by rounding amounts. Invalid/out-of-atlas UV rectangles are skipped rather than clamped. Singular transforms follow tiny-skia's handling. Temporary memory is one RGBA glyph crop, up to the atlas dimensions; shaping, glyph quads and picking geometry are not altered by this adapter. |
| Schemas | `oneOf` now requires exactly one valid branch. `allOf` retains every constraint, including repeated constraints on a property. Previously ignored keywords, local references and invalid schemas now receive library validation. Unknown-field warning/promotion is still Qiyas policy, including shared field names across flattened object parts. Reference specialization follows the registry's inline schemas and 2020-12 prefix-item vocabulary; custom legacy-draft schemas with unresolved step values are not a new supported contract. |
| Schema diagnostics | Existing required/type/enum/const/number/array wording and JSON-pointer escaping are retained, as are the filled registry repair example and required-field contract generation. Newly supported keywords and ambiguous `oneOf` use library wording. Error iteration order can differ; no existing assertion was changed to accommodate it. Branch selection is used for diagnostics/defaults only. Validator construction is not cached; performance has not been measured. |
| SSE | CR-only streams and empty `data` fields without a colon are parsed according to SSE. Malformed UTF-8 now reports a stream error instead of replacement characters. An initial BOM is stripped across chunk boundaries before the library, because 0.2.3 incorrectly slices it at byte 1. The original premature-close message and provider terminal policies remain. |
| Local date | Non-Unix systems now use their local date rather than UTC, notably near midnight. Timezone fallback/failure behavior belongs to chrono instead of the previous libc/null-result branch. |
| Diff diagnostics | Failure output is a JSON Patch, distinguishing missing keys from null and escaping pointer tokens. The independent before/after assertion is unchanged. |
| FNV, Adler, command distance | No intentional result changes: original hash seeds/bytes/masks and scalar-value edit-distance ranking are retained. This has not been verified by running tests. |
