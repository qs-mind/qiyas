# Local room detection, 29 October 2026

1. Room searches now start at each seed with a one-metre search radius and grow fourfold until the whole enclosure fits, following the hatch search. Only overlapping source bounds and segments enter the local graph. This radius is a numerical search parameter, not a design value. Completed graphs retain memoization, unchanged-face reuse and undo invalidation. Uncut joined wall faces are cached separately so every room does not rebuild the wall network.
2. Boundary/exclusion layers and existing annotation, grid, retained-region and opening roles are filtered before sampling, including block and xref children. Layer 0 inheritance is respected. Block bounds include transformed array corners without expanding the array. Analytic bounds cover curved polylines, arcs, multiline faces and spline control hulls; unavailable bounds remain conservative. A small filtered entry point in `qiyas-geom/src/flatten.rs` keeps ordinary flattening callers intact. Circular edges use the actual array instance transform.
3. Skipped rooms carry `reason` and `reason_ar`. Budget refusals identify boundary segments, flatten work or block depth, their counts/limits and leading contributors. Counts explicitly stop at refusal. Segment contributions use resolved layers; flatten work uses root reference layers and blocks. The existing `Boundary::TooDense` API remains compatible for other callers.
4. `FloorQuery` accepts the same flattened `boundary_layers` and `exclude_layers` policy as `RoomsQuery`. `space_check` forwards it to both room discovery and polygon/perimeter reads. Only these three small locations in `space_planning.rs` were changed by this task; concurrent edits there were preserved.

Tests are in the existing `goal_a.rs` module and `room_boundary.rs` unit module, so no new test registration is required. No existing test was changed or deleted.
