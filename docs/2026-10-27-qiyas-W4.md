## What is NOT verified

- Anything in the real WebKitGTK window: painting, the Thmanyah faces and swash in the live window,
  popovers and menus over the canvas, the WebGL canvas next to the new column, drag handles.
- The native Save dialog's placement under Hyprland (note 67's other half: the dialog appearing on
  workspace 1). The toast now says it is coming; the compositor's placement is not ours to fix from
  the web view and I could not test it.
- Ctrl+Tab, Ctrl+W, Ctrl+N and Ctrl+P as the WebKitGTK window receives them: the tests send the key
  events, they do not prove the web view does not eat one first (as F5 and F7 once could).
- `scripts/check.sh` as a whole, `cargo clippy`, the other crates' tests, the release speed guards.
  The Rust change is small (one function removed from `agent.rs`, two prompt lines, one test).
- Space-tap repeat and Enter-repeat feel: tested in jsdom; the risk is an accidental repeat.

## Things I noticed and did not change

- Follow-up done after review: a saved "POMI (RICS)" is migrated in Rust and written back, the name is
  matched as the same method (an old drawing keeps its rules), reports, exports and the name told to the
  model show the bare one; the output panels' own headings and buttons are folded into the head;
  `listComments` and `openCount` are gone; the column starts at 360 px in a window under 1300 px.
- `Ctrl+F` follows the founder's list (Find); AutoCAD's meaning (object snap) is F3 here. Say if you
  want AutoCAD's.
- A citation or note the model or the user writes with the body's name in it (bracketed or bare) is shown without it in reports
  and exports, but text in the drawing itself is theirs and is not touched.
- `samples/kareem-tests/` is untracked and was not touched.
