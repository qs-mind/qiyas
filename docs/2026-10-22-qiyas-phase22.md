# Phase 22: quantity deliverables

Report layouts live in drawing knowledge kind `reports`, written with `set_knowledge`, or
in `project.reports` in a `.qss`, written with `project.set_reports`. Both use the existing
single-step undo history. No measurement standard or trade wording is built into the renderer.
The neutral bilingual layouts ship in `crates/qiyas-core/src/deliverables/defaults.json`.

A layout contains `heading: {en, ar}`, ordered `columns` (`field`, bilingual `heading`, relative
`width`, `total`), optional `sections` with exact field filters, `group_by`, `total_heading`,
`page` (exact millimetres, margin and font size), `font` (system font filename), optional
`register_rules` for drawing title-block extraction, and optional `client`. Stored layouts are
readable with the `knowledge_reports` record collection.
Totals are computed from engine output and always partitioned by unit. No rate/amount fields
are supplied to the report engine. Dimension rows retain signed deductions, inclusion decisions,
timesing, factors, expressions, method citations and drawing/handle/sheet/grid references.

Use the registry through Mizan's existing run operation:

```json
{"type":"deliverable.export","kind":"boq","format":"excel","language":"ar","layout":"client","path":"deliverables/boq.xlsx"}
```

`kind`: `dimensions`, `boq`, `queries`, `variation`, `register`; `format`: `excel`, `pdf`.
The canonical registry wire form is `type: "deliverable", kind: "export", report: "boq"`;
the dotted shorthand above is normalized at the input boundary. `layout` is optional;
`language` defaults to `en`. Add `project: "Example.qss"` to export
saved aggregate data. Run the project after changing drawings. Variations use the drawing's
Phase 20 result; run `variation_report` after remeasurement. A drawing export without a
variation result reports that absence. Project runs retain each drawing's variation and queries.
All source-template and destination paths stay within the source drawing/project folder,
including symlinks. An export is written to a temporary file then replaced atomically.

```sh
qiyas-cli export drawing.dxf --kind dimensions --format pdf --language ar --path dimensions.pdf
qiyas-cli export /path/to/Example.qss --kind boq --format excel --path boq.xlsx
qiyas-cli project run /path/to/Example.qss --deliverables all --formats excel,pdf --language ar
```

The existing project workbook and morning report remain available. `--layout` selects a stored
layout; `--out` selects the project output folder (deliverables remain confined to the project
folder). JSON script commands use the same writer. Desktop and AI/MCP registry hosts complete
the prepared export outside core; core does not depend on workbook or PDF libraries.

PDF text uses `TextEngine` and the plotting `FontSet`: bidi shaping, embedded subsets,
ToUnicode and per-glyph ActualText. Fonts that cannot be embedded use plotting outlines plus
a searchable hidden text layer. The layout requests Thmanyah through existing system font
loading; bundled Noto is the loader's fallback. No font files are added. Text wraps and pages
without truncating references. Excel carries a chunked `Qiyas record` sheet; PDF carries an
embedded JSON record. These records enable lossless round trips without parsing presentation.

## Client workbook mapping

Mizan reads the workbook using the existing document reader, then writes this mapping into a
layout's `client` property. All coordinates are one-based; item identities and units must match
both the workbook and the computed BOQ. Every generated item must map exactly once. Multiple
sheets, header rows, section rows and arbitrary columns are supported.

```json
{"path":"client.xlsx","sheets":[{"name":"Sheet1","header_rows":[1,2],"section_rows":[3],"item_column":1,"description_column":2,"unit_column":3,"quantity_column":4,"protected_columns":[5,6],"items":[{"row":4,"code":"A1","unit":"m2","section":"Section A"}]}]}
```

The writer changes only the mapped existing quantity cells in a copy of the OOXML workbook.
Their style attributes remain; other worksheet bytes, rates, amounts, formulas, drawings,
merges, widths, heights, freeze panes, styles and other ZIP members remain unchanged. It does
not rebuild the client's workbook with rust_xlsxwriter or insert a report record into it.
Missing/ambiguous items, changed identities/units, duplicate mappings, protected columns and
header/section destinations fail before replacing the output. Legacy `.xls` is readable as
input data but client write-back requires an OOXML workbook.

## Verification

`qiyas-boq/tests/deliverables.rs` covers five kinds × two scopes × two languages × two formats,
lossless records and Arabic heading extraction through `pdftotext`. A styled client fixture
checks every ZIP member and compares the modified worksheet to the original with only the
quantity value substituted, including untouched rate and formula cells. It also checks layout
undo and confinement. Existing registry and AI surface tests enforce the take-off kit budget.
