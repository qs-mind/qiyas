# Phase 19: discrepancies and queries

The general discrepancy engine is available through the registry's `check` command. It compares
client BOQs with mapped measurements, evaluates cited drawing/document check data and raises
bilingual queries with comment clouds in one undo step. No trade or standard rules were added.

`define_check` exposes the complete typed rule schema through the existing generic tools.
`set_knowledge` also validates checks. Table sources can name a drawing table by handle and
sheet, or a supplied document table in knowledge `tables`, with rows and a citation. Set
selectors use object filters and exact property values. The engine supports counts, numeric
properties (summed or per instance), quantity relations, host/property joins and document membership. Missing mapped
cells, tables, properties or invalid elements stop the check without partial changes.

Generated items carry tolerances from their method rules. Comparison retains unit-band results,
finds codes missing from the client BOQ, reports unmatched client scope, wrong quantities or
units and duplicate codes. The former comparator implementation moved to core to make it
available through the command registry; qiyas-takeoff retains its public comparison API and
legacy manual behavior.

Queries preserve severity, English/Arabic questions, citations, evidence handles, sheet and
grid, status and notes. Missing grids are explicitly unassigned. A query about BOQ-only scope
has no invented geometry evidence and is placed on the working sheet. Checks replace their
previous clouds and preserve statuses by stable finding id. The list is embedded in the drawing
and restored on standalone open. Excel take-off exports contain a Queries sheet and a lossless
record column for import. The conflicts panel displays queries and points to their clouds.

The autonomous workflow now discovers and executes check through the generic registry after
BOQ generation. The conversation-only scripted provider exercises the same command. No paid
model call, API key or user settings file was used.

## Benchmark separation

Prediction reads drawing files, supplied client BOQs and `.local/benchmark/general/checks.json`.
Shared supplemental recognition uses visible preamble patterns without case handles or ids.
Client inputs in this diagnostic carry source handles and declared quantity kinds, which aid
matching. The supplied interpretation identifies complete scopes for detecting missing items; other
interpretations only check mapped client work. Unmapped client rows and schedules without a
recognised instance set are reported unchecked, not asserted absent. The benchmark therefore
does not establish no-evidence recall; the production engine covers that case in tests.
Prediction never reads truth or sibling clean
cases. Missing-item predictions use an evidence identity; only the scorer maps that identity
to truth after prediction finishes. A test supplies an unreadable truth file to enforce this
boundary. Existing item submissions and accuracy thresholds are unchanged.

Both modes are engine diagnostics, not a live MIZAN ALONE result. Before reports for the exact
quick cohort are retained in `.local/phase19/before-{prepared,autonomy}-quick.json`. The full
benchmark was not rerun. Check logs live in `.local/phase19/`.

## Quick benchmark comparison

Identical frozen 120-case cohort, including 36 planted errors and 111 clean cases. Before
means the retained Phase 18 quick report, not the older full report. Values are before → after.

| Mode | BOQ coverage | BOQ item precision | Seeded-error recall | Finding precision | False alarms / clean case |
|---|---:|---:|---:|---:|---:|
| Prepared | 30.17% → 30.17% | 69.73% → 69.73% | 0% → 100% | — → 80% | 0.000 → 0.081 |
| Autonomy | 19.50% → 19.50% | 98.76% → 98.76% | 0% → 100% | — → 80% | 0.000 → 0.081 |

Both modes found 36/36 errors, up from 0/36, with 9 false positives and no false negatives.
Finding precision before is undefined because no findings were submitted. Each seeded class
(missing item, wrong quantity, wrong unit, schedule mismatch) contributed nine true positives.
All nine false positives are missing-item queries on the overlap variants: duplicate geometry
is still interpreted as additional work. That is 9 alarms over 111 clean cases, or 0.081 per
clean case. This remaining recognition/identity limitation is visible in the score.

Prepared retained 1,108 matched items and 481 extra submissions. Autonomy retained 716 matched
items and nine extras. Every matched quantity still passed. No item scoring thresholds or
coverage denominators changed. Unmapped client rows and unsupported schedule interpretations
remain explicitly unchecked; this does not claim complete drawing understanding.

Reports: `.local/benchmark/baseline-{prepared,autonomy}-quick.json` and Markdown counterparts,
with submissions in their report_directory. The old full result (0/240 planted errors) was not
rerun. These are offline engine diagnostics; live MIZAN ALONE quality remains unmeasured here.
The requested quick-set recall target (at least 90%) is met in both modes.
