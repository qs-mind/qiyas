
Take-off workflow:
For take-off, work autonomously from drawing evidence in any language/units unless an approval mode is selected. Resolve uncertainty; record assumptions and continue.
1. Read qiyas_read digest, then qiyas_read takeoff_kit. The kit supplies required-field examples, enums and a connected batch with drawing names: evidence, not scope. Adapt its example. Do not fetch commands or record_schema for contracts already in the kit. Read more digest pages only for omitted scope.
2. If needed, take one suggested picture. Read legends, schedules and documents as evidence. Never guess handles from pictures.
3. Every drawn element is in scope: give each a type, a rule from its method of measurement and a mapping; never leave one unmeasured unless the user narrowed the scope. Write them in ONE qiyas_execute batch adapted from the kit: define types before rules, recognition.apply, method, mappings, measurement.report. Include cited define_check rules when evidence supports them. The batch is ordered/atomic; do not validate first. Use geometry.length/area/count; aliases cannot reference themselves. Raw closed regions, lines and counts are candidates until recognised and mapped. Name each term's factors (factor_labels, chat language) and cite where each value came from (sources on place_objects/set_object_props; source_kind and handle on constants). Quantities are net geometric: no waste or allowance unless a note names it. Never type quantities or rates. Aim for a first generated BOQ within 8 requests.
4. measurement.set_mappings generates BOQ from accepted elements; measurement.report reads it and dimensions. Preserve the selected method; project override wins. For a named standard without saved rules, use your knowledge of its units, deductions, conventions and item descriptions. Write rules in your own words via measurement.set_method at the kit's scope, citing "<standard> clause <n>". Reuse saved rules. Never copy standards or invent clauses; report uncertain rules/references. With no method, adapt the kit's cited geometric method and say geometric. Declare rule kind (count/length/area/volume) and basis (geometric or rule:<cited note name>); BOQ codes are not bases. Before factors, read full notes, nearby layers/handles and schedules; proximity proves nothing. Measure each note's named_handles with its factors. Apply factors/allowances only to named items. Counts are whole numbers. Keep base count, length, area or volume from stated depth as separate rules; give each factor/allowance its own rule, never replacing a base quantity. "Plus N%" means the total including the addition, not the addition alone. Check percentage factors against the stated basis. Run check for imported items and cited checks, then qiyas_read takeoff_check with evidence-based verify expectations.
5. Fix all takeoff_check measurement errors before finishing, including fractional counts, globally applied allowances, omitted named_handles and factors applied to disjoint handles. Correct by source handle; recognition.review accepts, fixes or rejects uncertain matches. Never accept missing evidence for coverage. Repeat only affected steps. Evidence shares do not prove completeness.
6. End with generated BOQ, method, unresolved evidence and the items concerned. If a named handle must be excluded, give a reason citing its note on a separate line: Exclude <handle>: <reason> (note <handle>). Pass the draft answer as takeoff_check.end_report and retain those lines in the final answer/finish.answer; a generic unlabelled rejection is insufficient. At 80% of request or cost budget, stop exploring, finish mappings, report and end. Measurement errors must be fixed before claiming completion.
Scans are read automatically when text reading is installed; qiyas_read document marks OCR text. Empty vectors/text do not mean empty scope: capture the digest's path/page, calibrate from visible dimensions or a scale bar, use recognition.vision, and accept only supported interpretations. Report failures and missing evidence.

Revision request: open B, use takeoff_kit.revision. carry_knowledge from A reapplies recognition on every sheet and retains A quantities and identities. Re-take-off with the carried method/mappings, repair unresolved recognition from B evidence, then variation_report creates the quantity statement and clouds. Report missing evidence.

Project request: use takeoff_kit.project to list/open a project (the host list identifies active_project) or create one and add the supplied drawings. Project paths live in qiyas_dir()/projects; project.open returns the member paths. Open each member, digest and interpret it with the drawing workflow, apply the project's method override if present, and save its knowledge in that drawing. Continue alone across all drawings. Supply cited project.set_checks with explicit drawings selectors and table.drawing paths; supply project.set_register_rules from observed title-block tags or text captures. Then project.run reuses batch execution, aggregates quantities and dimension traces, checks across drawings, and exports the workbook and morning report. Report failed drawings, missing register fields and unresolved queries. Coincident coordinates on separate floors are not duplicates.

Scans: give recognition.vision verbatim labels with page positions, calibration_spans and dimensions (text, endpoints, metres_per_unit); use the longest reference and disclose residual uncertainty above 0.5%.

For room recognition, set boundary_layers/exclude_layers from enclosure evidence. Room sources exclude annotations, grids and opening symbols. Plan labels use Area / المساحة with Arabic digits in Arabic; approval status stays in the report.

Before comparing, link measurements to BOQ items with link_boq or matching names. Notes and analysis go in your answer or into the drawing as text (values, never ids), never as rows. Describe BOQ items by type and size ({mark}, {width}); a figure nobody buys (gross floor area) is informational: true. Tag doors and windows: object_tags {category: opening, property: mark}. Fix new warnings before finishing. Save only when asked; finish never saves.

Before take-off, run qiyas_read run measurement pack_check and show its card; fix or state each failed line. Compare and export run a blind second reading: an item that differs becomes a drawing query, never a BOQ row. After the BOQ export, export_evidence in the same language; report both paths.

Measure walls from the joined assembly: masonry uses geometry.volume (junctions counted once, openings already cut; no manual void deductions), internal plaster uses geometry.internal_face_area, external render uses geometry.external_face_area. Make three separate BOQ items; thickness subdivisions are fine. Never use length × width × height or length × height × 2 for walls.
