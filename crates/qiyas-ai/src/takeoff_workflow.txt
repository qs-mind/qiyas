
Take-off workflow:
For take-off, work alone from drawing evidence in any language or units. Human review is optional. The drafting phases and ambiguity questions above apply to drafting; resolve take-off uncertainty from evidence, record assumptions and continue. Respect an explicitly selected approval mode; autonomous is the default.
1. Read qiyas_read digest, then qiyas_read takeoff_kit. The kit is complete; do not call commands for anything in it. It supplies complete required-field examples, enum values and one connected batch with drawing layer/block names. Names in that batch are illustrative evidence, not a scope classification. Never validate stubs: start from the kit's example. Do not fetch commands or record_schema for contracts already in the kit. Read further digest pages only when needed for omitted scope.
2. Take one suggested picture if interpretation needs it. Read legends, schedules and source documents as evidence. Never guess handles from a picture.
3. Write everything for supported scope in ONE qiyas_execute batch adapted from the kit: define types before rules, recognition.apply, method, mappings, measurement.report. Include cited define_check rules when evidence supports them. The batch is ordered and atomic. Do not validate first. Use geometry.length/area/count for quantity expressions; self-referencing aliases are invalid. Raw closed regions, lines and counts are candidates until recognised and mapped. Never type quantities or rates. Aim for a first generated BOQ within 8 requests.
4. Apply and report in that batch: measurement.set_mappings generates the BOQ automatically from accepted elements; measurement.report reads it and its dimension sources. Preserve a method loaded from Settings (project override wins). If none is selected, adapt the kit's cited geometric method and say geometric. Declare each measurement rule kind (count, length, area, volume) and basis (geometric or rule:<cited note name>); a BOQ code is not a basis. Check the full note text, closest layers/handles and schedule columns before applying factors. Proximity does not prove applicability. Elements in a note's named_handles are in scope: measure them and apply that note's factors to them. Factors and allowances apply only to the items their note names. Counts are whole numbers. Keep every base measurement (an element's count, length, area, or volume from its stated depth) as its own rule, and give each factor or allowance its own rule; never replace a base quantity with an adjusted one. When a clause says a quantity "plus N%", that rule's quantity is the total including the addition, not the addition alone. Check percentage factors against the stated quantity basis. Never invent standards. Run check after the BOQ to compare imported items and evaluate cited checks. Run qiyas_read takeoff_check with evidence-based verify expectations.
5. Fix all takeoff_check measurement errors before finishing, including fractional counts, globally applied allowances, omitted named_handles and factors applied to disjoint handles. Re-read the cited note and correct its scope. Fix errors using the returned errors, full required-field lists and filled examples. Correct by source handle; recognition.review accepts, fixes or rejects uncertain matches without a human approval step. Never accept missing evidence for coverage. Repeat only affected steps. Evidence shares for layers, inserts, regions and schedules are not proof of project completeness.
6. End with generated BOQ, method, unresolved evidence and low-confidence items. If a named handle must be excluded, give a reason citing its note on a separate line: Exclude <handle>: <reason> (note <handle>). Pass the draft answer as takeoff_check.end_report and retain those lines in the final answer/finish.answer; a generic unlabelled rejection is insufficient. At 80% of request or cost budget, stop exploring, finish mappings, report and end. Unresolved evidence does not require human review; measurement errors must be fixed before claiming completion. Do not spend remaining requests on schema discovery or another plan.
For scans, empty vector/text results do not mean empty scope. Capture the document using the digest's path/page, calibrate from visible dimensions or a scale bar and use recognition.vision hints snapped to raster ink. Review pending geometry and accept only supported interpretations. If capture, calibration or recognition fails, report the actual failure and missing evidence; never claim a missing scale without inspecting the page.

Revision request: open B, use takeoff_kit.revision. carry_knowledge from A reapplies recognition on every sheet and retains A quantities and identities. Re-take-off with the carried method/mappings, repair unresolved recognition from B evidence, then variation_report creates the quantity statement and clouds. export_takeoff includes Variation. Report missing evidence; never type quantities or rates.

Project request: use takeoff_kit.project to list/open a project (the host list identifies active_project) or create one and add the supplied drawings. Project paths live in qiyas_dir()/projects; project.open returns the member paths. Open each member, digest and interpret it with the drawing workflow, apply the project's method override if present, and save its knowledge in that drawing. Continue alone across all drawings. Supply cited project.set_checks with explicit drawings selectors and table.drawing paths; supply project.set_register_rules from observed title-block tags or text captures. Then project.run reuses batch execution, aggregates quantities and dimension traces, checks across drawings, and exports the workbook and morning report. Report failed drawings, missing register fields and unresolved queries. Never infer duplicate identity from coincident coordinates across separate floors.
